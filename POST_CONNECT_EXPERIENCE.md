# Ironclad Connector — что видит и чем управляет пользователь после подключения

## 1. Целевой пользователь
Юрист/менеджер по контрактам (Legal Ops) в компании среднего/крупного размера,
использующей Ironclad как CLM (Contract Lifecycle Management) систему.

## 2. Момент истины после подключения
Сразу после `connect_ironclad` — `audit_contract_health`: сколько активных договоров,
сколько истекает в ближайшее время, сколько workflow застряло на каком-то шаге.

## 3. Что пользователь видит
- Записи (готовые/подписанные договоры) со всеми атрибутами — `list_records`,
  `get_record`.
- Договоры, которые скоро истекают/требуют продления — `find_expiring_contracts`.
- Активные workflow (контракты в процессе согласования) — `list_all_workflows`.
- Статус подписания конкретного контракта — `get_signature_status`.
- Обязательства (обязанности по контракту с датами) — `list_obligations`.
- Контрагентов (компании/физлица, с которыми заключены договоры) — `list_entities`.
- Схему записей (какие типы контрактов настроены и какие у них поля) —
  `get_records_schema`.

## 4. Чем пользователь может управлять
- Запускать новый workflow согласования контракта из шаблона — `launch_workflow`,
  массово — `bulk_launch_workflow`.
- Утверждать/отклонять шаг согласования — `update_approval`.
- Отправлять контракт на подпись, когда согласование завершено —
  `send_signature_request`.
- Применять пост-подписные действия (продлить, расторгнуть) — `apply_contract_action`.
- Создавать обязательства с дедлайнами (например "напомнить о продлении за 60 дней") —
  `create_obligation`.
- Отменять workflow, вернуть на этап Review — `cancel_workflow`,
  `revert_workflow_to_review`.
- Импортировать уже подписанный документ (миграция из другой системы) с помощью AI-
  извлечения полей — `smart_import_record`.

## 5. "Вау"-момент для демо потенциальному клиенту
"Смотри — говорю Webbee: 'какие договоры истекают в следующие 60 дней?'. Она находит их
через `find_expiring_contracts`, а я прошу запустить workflow продления для одного —
`launch_workflow` стартует процесс согласования сразу."

## 6. Что делает это "заточенным под него"
`get_records_schema` читает реальные типы контрактов и их поля, настроенные именно этой
юридической командой (например "Territory" и "Auto-Renewal Clause" для дистрибьюторских
соглашений) — а не универсальный шаблон NDA.
